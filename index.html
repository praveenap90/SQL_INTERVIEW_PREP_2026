Key Concepts (12)

INNER JOIN
Returns only rows where both tables have a match on the join key.
LEFT JOIN
Returns all rows from left, with NULLs for missing matches from right.
GROUP BY
Aggregates rows by columns; must include all non-aggregated columns.
HAVING vs WHERE
HAVING filters aggregated results; WHERE filters individual rows.
CTE
Named subquery with WITH; scoped to single statement; improves readability.
Window Function
Computes across partition without collapsing rows. Syntax: FUNC() OVER (PARTITION BY...)
ROW_NUMBER()
Unique sequential integers; never skips. Ties: 1,2,3,4,5
RANK()
Ranks with gaps on ties. Result: 1,2,2,4,5
DENSE_RANK()
Ranks without gaps on ties. Result: 1,2,2,3,4
NULL Comparison
Use IS NULL. Comparisons = <> return NULL, not TRUE/FALSE.
Subquery
Query within query. Types: scalar, IN/EXISTS, correlated.
Correlated Subquery
References outer query. Executes once per row (slower).

Practice Q&A (80 Interview Questions)

Q: Difference between INNER JOIN and LEFT JOIN?
INNER JOIN returns only matching rows. LEFT JOIN returns all rows from left table + matches from right (NULLs for non-matches).
Q: GROUP BY and HAVING clauses?
GROUP BY aggregates rows by columns. HAVING filters aggregated results (like WHERE for aggregates).
Q: Purpose of LIMIT clause?
LIMIT restricts the number of rows returned, useful for pagination and preventing large result sets.
Q: How DISTINCT works?
DISTINCT removes duplicate rows from results, keeping only unique values.
Q: Purpose of ORDER BY?
ORDER BY sorts results by specified columns in ASC (ascending) or DESC (descending) order.
Q: Explain self-join?
Self-join joins a table to itself using table aliases to find relationships within the same table (e.g., employee-manager).
Q: Five aggregate functions?
COUNT(), SUM(), AVG(), MIN(), MAX() - compute single values from multiple rows.
Q: WHERE vs HAVING?
WHERE filters individual rows before grouping. HAVING filters aggregated results after grouping.
Q: CTEs and when to use?
CTEs (WITH clause) are named subqueries. Use for readability, recursion, and reusability within a single statement.
Q: Correlated subqueries example?
Subquery that references outer query: SELECT * FROM employees e WHERE salary > (SELECT AVG(salary) FROM employees WHERE dept_id = e.dept_id)
Q: IN vs EXISTS?
IN checks membership in a list. EXISTS checks if subquery returns rows (EXISTS is faster for large sets).
Q: Window functions explained?
Functions that compute over a window (partition) of rows without collapsing them. Syntax: FUNC() OVER (PARTITION BY ... ORDER BY ...)
Q: ROW_NUMBER() vs RANK() vs DENSE_RANK()?
Aspect ROW_NUMBER() RANK() DENSE_RANK()
Purpose Sequential numbering Ranking with gaps Ranking without gaps
On Ties Unique numbers Same rank, next skip Same rank, continuous
Example 1, 2, 3, 4, 5 1, 2, 2, 4, 5 1, 2, 2, 3, 4
Use Case Unique row IDs, pagination Sports rankings, scores Grade levels, categories
Top-N Queries Top 3 = exactly 3 rows Top 3 rank = 5+ rows if ties Top 3 rank = 3-4 rows
Q: When to use scalar subquery?
Use scalar subquery in SELECT clause to return single value per row, like (SELECT MAX(salary) FROM salaries).
Q: PARTITION BY explained?
PARTITION BY divides rows into groups for window function calculation. Each partition is calculated independently.
Q: RANK() vs DENSE_RANK()?
Feature RANK() DENSE_RANK()
Ties Handling Same rank for tied values Same rank for tied values
Next Rank After Tie Skips numbers (gaps) Continuous (no gaps)
Example Sequence 1, 2, 2, 4, 5 1, 2, 2, 3, 4
Top-N Query WHERE RANK() = 3 → 1 row WHERE DENSE_RANK() = 3 → 1 row
Top 3 WHERE RANK() ≤ 3 → 4+ rows if ties WHERE DENSE_RANK() ≤ 3 → 3-4 rows
Best For Competition rankings (olympics) Tier classifications, levels
Syntax RANK() OVER (ORDER BY col) DENSE_RANK() OVER (ORDER BY col)
Q: What is an index?
Index is a database object that improves query performance by creating a sorted lookup structure on columns.
Q: How to read EXPLAIN PLAN?
EXPLAIN PLAN shows query execution steps, costs, and row estimates. Lower cost is better. Look for full table scans.
Q: Avoid full table scans?
Add indexes on WHERE clause columns, filter early, avoid SELECT *, use proper data types for joining.
Q: UPDATE vs DELETE?
UPDATE modifies existing rows. DELETE removes rows. Use soft deletes (status flag) for important data.
Q: Why transactions matter?
Transactions ensure ACID properties: Atomicity, Consistency, Isolation, Durability. Critical for data integrity.
Q: Clustered vs non-clustered index?
Clustered: sorts/stores table data (one per table). Non-clustered: separate lookup structure (many per table).
Q: Query optimization techniques?
Add indexes, early filtering, avoid subqueries in WHERE, use EXPLAIN, denormalize if needed, partition large tables.
Q: Prevent N+1 queries?
Use JOIN instead of loops, batch load related data, use subqueries wisely, consider caching strategies.
Q: What is NULL?
NULL represents unknown/missing value. Comparisons with NULL return NULL (not TRUE/FALSE). Use IS NULL, IS NOT NULL.
Q: COALESCE vs IFNULL?
Both replace NULL: COALESCE(col1, col2, default) returns first non-NULL. IFNULL(col, default) checks single column.
Q: Handle NULL in JOINs?
NULL never matches NULL (even in JOINs). Use COALESCE in join condition or filter NULLs in WHERE clause.
Q: Best practices for dates?
Use DATE data type, avoid string comparisons, use DATE_TRUNC/DATEPART for comparisons, store UTC timezone.
Q: DATEADD, DATEDIFF, DATE_TRUNC?
DATEADD: add interval to date. DATEDIFF: difference between dates. DATE_TRUNC: round down to start of period.
Q: Calculate rolling windows?
Use DATEADD for offset: BETWEEN DATEADD(day, -30, CURRENT_DATE()) AND CURRENT_DATE() for last 30 days.
Q: Common data quality issues?
Duplicates, NULLs, whitespace, type mismatches, invalid dates, referential integrity violations. Detect with GROUP BY COUNT(*) > 1.
Q: Duplicate removal strategy?
Use ROW_NUMBER() OVER (PARTITION BY unique_cols ORDER BY id) = 1 or DELETE WHERE id NOT IN (SELECT MIN(id) GROUP BY cols).

Q: ALTER statement and use cases?
ALTER modifies database objects. Uses: add/drop/modify columns, rename tables/columns, add/remove constraints, change data types. Example: ALTER TABLE users ADD COLUMN last_login DATETIME;
Q: Views and their use cases?

Q: Local vs Global variables and differences?
Local Variables: Declared with @; scoped to batch/procedure/function; accessible only within that scope; destroyed after execution ends. Global Variables: Prefixed @@; system-defined (@@VERSION, @@IDENTITY, @@ROWCOUNT); accessible throughout session; maintained by database server. Example: @myVar (local), @@VERSION (global). Local for user data, global for system info.

Q: What is MERGE statement and its need?
MERGE combines INSERT, UPDATE, DELETE in one statement based on condition. Syntax: MERGE INTO target USING source ON condition WHEN MATCHED THEN UPDATE... WHEN NOT MATCHED THEN INSERT... Why needed: Efficient for upsert operations (update if exists, insert if not), reduces multiple statements, improves performance, simplifies logic. Use case: Synchronizing data between tables.
Q: Difference between COALESCE() and ISNULL()?
COALESCE(col1, col2, col3, default): Returns first non-NULL value; accepts multiple arguments; ANSI standard. ISNULL(col, replacement): Replaces NULL with value; takes exactly 2 arguments; SQL Server specific. Difference: COALESCE is portable, handles multiple columns; ISNULL is faster but limited. Example: COALESCE(col1, col2, 'Unknown') vs ISNULL(col, 'Unknown').
Q: Operator for appending two strings?
+ (Plus): Concatenates strings in SQL Server. Example: 'Hello' + ' ' + 'World' = 'Hello World'. || (Double Pipe): Used in PostgreSQL, Oracle, MySQL. CONCAT(): Function across databases; CONCAT('Hello', ' ', 'World'). Note: + treats NULLs as NULL result; CONCAT ignores NULLs. Prefer CONCAT for portability.
Q: Can we disable a trigger? If yes, how?
Yes, triggers can be disabled. SQL Server: DISABLE TRIGGER trigger_name ON table_name; or DISABLE TRIGGER ALL ON DATABASE. Re-enable: ENABLE TRIGGER trigger_name ON table_name. Why disable: Maintenance, bulk operations (performance), testing. Alternative: ALTER TABLE table_name DISABLE TRIGGER trigger_name; Don't delete trigger if you plan to use later.
Q: What is CASE WHEN in SQL?
CASE WHEN performs conditional logic (if-else). Syntax: CASE WHEN condition1 THEN value1 WHEN condition2 THEN value2 ELSE default END. Two forms: Simple (CASE col WHEN val THEN...) and Searched (CASE WHEN condition THEN...). Example: CASE WHEN salary > 100000 THEN 'High' WHEN salary > 50000 THEN 'Medium' ELSE 'Low' END. Use in SELECT, WHERE, ORDER BY clauses.
Q: Difference between NVL and NVL2 functions?
NVL(col, replacement): If col is NULL, return replacement; else return col. Oracle-specific. NVL2(col, if_not_null, if_null): If col is NOT NULL, return if_not_null; else return if_null. Also Oracle. Examples: NVL(commission, 0) = 0 if NULL; NVL2(commission, commission * 1.1, 0) = increased commission or 0. SQL Server equivalent: ISNULL for NVL.

Q: What is ETL in SQL?
ETL = Extract, Transform, Load: Extract: Pull data from source (databases, APIs, files). Transform: Clean, validate, aggregate, merge data (SQL queries, joins, aggregations). Load: Insert processed data into target warehouse/database. Why: Data quality, consolidation, analytics. Example: Extract sales data → Transform (remove duplicates, calculate totals) → Load to data warehouse. ETL jobs run scheduled, critical for BI.
Q: Fetch common records from two tables?
Using INTERSECT: SELECT col FROM table1 INTERSECT SELECT col FROM table2; Returns rows present in both. Using INNER JOIN: SELECT t1.col FROM table1 t1 INNER JOIN table2 t2 ON t1.id = t2.id; Using IN with subquery: SELECT col FROM table1 WHERE col IN (SELECT col FROM table2); Best choice: INTERSECT for simple matching, INNER JOIN for related rows with conditions. INTERSECT removes duplicates automatically.
Q: What are ACID properties?
A (Atomicity): Transaction all-or-nothing; either all succeed or all fail. C (Consistency): Database moves from valid state to valid state; no partial updates. I (Isolation): Concurrent transactions don't interfere; each sees consistent view. D (Durability): Committed data persists even after crashes. Why important: Guarantees data integrity in multi-user environments. Example: Money transfer must be atomic (debit + credit both succeed or both fail).
Q: Primary Key vs Unique Key difference?
Primary Key: Uniquely identifies each row; cannot be NULL; only one per table; clusters table by default; used for foreign key references. Unique Key: Ensures uniqueness; can be NULL (multiple NULLs allowed); multiple per table; non-clustered index; not used for foreign keys. Example: PK = employee_id; UK = email address (must be unique but not identity). Use PK for row identity, UK for business rules.
Q: What are Entities and Relationships?
Entity: Real-world object represented as table (e.g., Employee, Customer, Product). Has attributes (columns) and unique identifier (primary key). Relationship: Association between entities (e.g., Employee works in Department). Types: One-to-One (1:1), One-to-Many (1:M), Many-to-Many (M:M). In ER Diagram: Entities are boxes, relationships are lines connecting them. Example: Employee entity related to Department via dept_id foreign key. Relationships ensure data integrity and normalization.
Q: Stored procedures and advantages?
Pre-compiled SQL code stored in DB. Advantages: reusable, better performance, security, reduced network traffic.
Q: Procedure input/output parameters?
Input: pass data in (@param INT). Output: return data out (@result INT OUTPUT). Use OUTPUT keyword to modify caller variables.
Q: Triggers and when to use?
Triggers automatically execute on data changes. Use for: audit logs, validation, enforcing business rules. Use sparingly (debugging hard).

Q: Scheduled events/tasks?
Scheduled jobs that run SQL automatically (e.g., CRON tasks). Use for: backups, archiving, reporting, ETL jobs.
Q: Debug stored procedures?
Use PRINT statements, SELECT for debugging, TRY-CATCH blocks, check RAISERROR, test with sample data first.
Q: Views and use cases?
Views: saved SELECT queries. Use for: abstraction, security (restrict columns), simplifying complex queries, data consistency.
Q: Transactions and ROLLBACK?

Q1: Find the second highest salary from the Employee table?
Solution 1: Using OFFSET
SELECT DISTINCT salary FROM employees ORDER BY salary DESC LIMIT 1 OFFSET 1;
Solution 2: Using Subquery
SELECT MAX(salary) FROM employees WHERE salary < (SELECT MAX(salary) FROM employees);
Solution 3: Using CTE
WITH ranked_salaries AS (SELECT DISTINCT salary, ROW_NUMBER() OVER (ORDER BY salary DESC) AS rank FROM employees) SELECT salary FROM ranked_salaries WHERE rank = 2;

Q2: Find duplicate records in a table (by email)?
Solution 1: Using GROUP BY HAVING
SELECT email, COUNT(*) FROM users GROUP BY email HAVING COUNT(*) > 1;
Solution 2: Using Window Function
SELECT email, COUNT(*) OVER (PARTITION BY email) AS cnt FROM users WHERE COUNT(*) OVER (PARTITION BY email) > 1;
Solution 3: Show duplicate records
SELECT * FROM users WHERE email IN (SELECT email FROM users GROUP BY email HAVING COUNT(*) > 1);

Q3: Get top 3 employees by salary in each department?
Solution: Using Window Function
WITH ranked_emp AS (SELECT *, ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rank FROM employees) SELECT * FROM ranked_emp WHERE rank <= 3;
Alternative: Using CTE + GROUP BY
SELECT dept_id, employee_name, salary FROM employees e1 WHERE salary IN (SELECT DISTINCT salary FROM employees e2 WHERE e2.dept_id = e1.dept_id ORDER BY salary DESC LIMIT 3);

Q4: Calculate running total of sales by date?
Solution: Using Window Function
SELECT order_date, amount, SUM(amount) OVER (ORDER BY order_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total FROM sales ORDER BY order_date;
Explanation: ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW sums from first row to current row.
EASY
Q5: Get employee name with their manager's name (self-join)?
Solution: Self Join
SELECT e.employee_name, m.employee_name AS manager_name FROM employees e LEFT JOIN employees m ON e.manager_id = m.employee_id;
Explanation: Join table to itself using aliases (e for employee, m for manager). Use LEFT JOIN to include employees without managers.

Q6: Get sales in the last 30 days with dynamic date?
Solution: Using DATEADD/DATE_TRUNC
SELECT * FROM sales WHERE order_date BETWEEN DATEADD(day, -30, CURRENT_DATE()) AND CURRENT_DATE();
PostgreSQL Version:
SELECT * FROM sales WHERE order_date >= CURRENT_DATE - INTERVAL '30 days' AND order_date <= CURRENT_DATE();
Best Practice: Always use dynamic dates (CURRENT_DATE) for maintainability.

Q7: Calculate average salary excluding NULL values?
Solution: AVG() ignores NULLs automatically
SELECT AVG(salary) FROM employees;
With NULL replacement:
SELECT AVG(COALESCE(salary, 0)) FROM employees;
Note: AVG() skips NULLs, but COALESCE replaces them. Choose based on business logic.

Q8: Remove leading/trailing whitespace from names?

SELECT name, TRIM(name) AS cleaned FROM users WHERE name != TRIM(name);

WITH monthly_sales AS (SELECT p.product_id, p.product_name, YEAR(o.order_date) AS year, MONTH(o.order_date) AS month, SUM(oi.quantity * oi.price) AS monthly_sales FROM products p JOIN order_items oi ON p.product_id = oi.product_id JOIN orders o ON oi.order_id = o.order_id GROUP BY p.product_id, p.product_name, YEAR(o.order_date), MONTH(o.order_date)), sales_with_lag AS (SELECT *, LAG(monthly_sales) OVER (PARTITION BY product_id ORDER BY year, month) AS prev_month_sales FROM monthly_sales) SELECT product_id, product_name, year, month, monthly_sales, prev_month_sales FROM sales_with_lag WHERE prev_month_sales > 0 AND monthly_sales >= (prev_month_sales * 2) ORDER BY product_name, year, month;

Q142: Find employees who have been promoted but their salary didn't increase?

WITH promotions AS (SELECT e.employee_id, e.employee_name, pr.promotion_date, pr.new_job_title, pr.new_salary_after_promotion FROM employees e JOIN promotion_records pr ON e.employee_id = pr.employee_id), prev_salary AS (SELECT p.employee_id, p.employee_name, p.promotion_date, p.new_salary_after_promotion, LAG(sh.salary) OVER (PARTITION BY p.employee_id ORDER BY sh.salary_date) AS salary_before_promotion FROM promotions p LEFT JOIN salary_history sh ON p.employee_id = sh.employee_id AND sh.salary_date < p.promotion_date) SELECT DISTINCT employee_id, employee_name, promotion_date, salary_before_promotion, new_salary_after_promotion FROM prev_salary WHERE salary_before_promotion >= new_salary_after_promotion ORDER BY employee_name;

Q162: Find the nth highest salary in a company (e.g., 5th highest)?

DECLARE @n INT = 5; WITH ranked_salaries AS (SELECT DISTINCT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk FROM employees) SELECT TOP 1 salary FROM ranked_salaries WHERE rnk = @n;

Q163: Find employees whose salaries are between the 25th and 75th percentile?
Solution: Using PERCENTILE_CONT function
WITH salary_percentiles AS (SELECT PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY salary) OVER () AS p25, PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY salary) OVER () AS p75 FROM employees) SELECT e.employee_id, e.employee_name, e.salary FROM employees e CROSS JOIN salary_percentiles sp WHERE e.salary BETWEEN sp.p25 AND sp.p75 ORDER BY e.salary;
Alternative without PERCENTILE_CONT:
WITH ranked_salaries AS (SELECT DISTINCT salary, PERCENT_RANK() OVER (ORDER BY salary) AS pct_rank FROM employees) SELECT e.employee_id, e.employee_name, e.salary FROM employees e WHERE e.salary IN (SELECT DISTINCT salary FROM ranked_salaries WHERE pct_rank BETWEEN 0.25 AND 0.75);

Q166: Calculate the difference between each order amount and the previous order amount per customer?
Solution: Using LAG window function
WITH order_amounts AS (SELECT c.customer_id, c.customer_name, o.order_id, o.order_date, SUM(oi.quantity * oi.price) AS order_total FROM customers c JOIN orders o ON c.customer_id = o.customer_id JOIN order_items oi ON o.order_id = oi.order_id GROUP BY c.customer_id, c.customer_name, o.order_id, o.order_date), with_lag AS (SELECT customer_id, customer_name, order_id, order_date, order_total, LAG(order_total) OVER (PARTITION BY customer_id ORDER BY order_date) AS prev_order_total FROM order_amounts) SELECT customer_id, customer_name, order_id, order_date, order_total, prev_order_total, ROUND(order_total - prev_order_total, 2) AS difference FROM with_lag WHERE prev_order_total IS NOT NULL ORDER BY customer_id, order_date;

Q167: Write a recursive query to get all descendants of a manager?

Q168: Find products with sales increasing every month for the last 3 months?
Solution: Using window functions for month-over-month comparison
WITH monthly_product_sales AS (SELECT p.product_id, p.product_name, YEAR(o.order_date) AS year, MONTH(o.order_date) AS month, SUM(oi.quantity * oi.price) AS sales FROM products p JOIN order_items oi ON p.product_id = oi.product_id JOIN orders o ON oi.order_id = o.order_id WHERE o.order_date >= DATEADD(month, -3, GETDATE()) GROUP BY p.product_id, p.product_name, YEAR(o.order_date), MONTH(o.order_date)), sales_with_lag AS (SELECT product_id, product_name, year, month, sales, LAG(sales) OVER (PARTITION BY product_id ORDER BY year, month) AS prev_month_sales FROM monthly_product_sales), growth_check AS (SELECT product_id, product_name, year, month, sales > prev_month_sales AS is_increasing FROM sales_with_lag WHERE prev_month_sales IS NOT NULL) SELECT DISTINCT product_id, product_name FROM growth_check WHERE is_increasing = 1 GROUP BY product_id, product_name HAVING COUNT(*) >= 2;
