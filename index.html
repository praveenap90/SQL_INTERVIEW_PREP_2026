📋 Module 1: SELECT Fundamentals

Concepts: SELECT, FROM, WHERE, ORDER BY, LIMIT, DISTINCT

Real-world example: Fetching top 10 customers by revenue with filters and sorting.

SELECT customer_id, SUM(amount) as total
FROM orders
WHERE amount > 100
GROUP BY customer_id
ORDER BY total DESC
LIMIT 10;
Always use LIMIT in early query development to avoid returning millions of rows.

🐍 SQL vs. Pandas Quick Reference

# Task SQL Pandas
1 Select columns SELECT col1, col2 FROM table df[['col1', 'col2']]
2 Filter rows SELECT * FROM table WHERE col > 5 df[df['col'] > 5]
3 Sort ORDER BY col DESC df.sort_values(by='col', ascending=False)
🔗 Module 2: JOINs & Table Relationships

Concepts: INNER JOIN, LEFT/RIGHT/FULL OUTER JOIN, CROSS JOIN, Self-joins

SELECT o.order_id, c.customer_name, p.product_name
FROM orders o
INNER JOIN customers c ON o.customer_id = c.customer_id
LEFT JOIN products p ON o.product_id = p.product_id;
LEFT JOIN preserves all rows from the left table, filling NULLs for missing matches.

📋 JOIN Decision Table

Scenario Use This Join Why
Only matching rows INNER JOIN Removes non-matches (fastest)
All from left table LEFT JOIN Keep incomplete records
All from both tables FULL OUTER JOIN Union of both sides
📊 Module 3: Aggregation & GROUP BY

Concepts: GROUP BY, HAVING, aggregate functions (COUNT, SUM, AVG, MIN, MAX)

SELECT category, COUNT(*) as count, AVG(price) as avg_price
FROM products
GROUP BY category
HAVING COUNT(*) > 5
ORDER BY avg_price DESC;
HAVING filters on aggregated results; WHERE filters on individual rows.

📊 Aggregate Function Reference

Function Purpose Example
COUNT(*) Count all rows COUNT(*) = 150
SUM(col) Total of numeric column SUM(amount) = 10000
AVG(col) Average value AVG(price) = 29.99

🔍 Module 4: Subqueries & CTEs

Concepts: Scalar subqueries, correlated subqueries, IN/EXISTS, Common Table Expressions (CTEs)

WITH high_value_orders AS (
  SELECT customer_id, COUNT(*) as order_count
  FROM orders
  WHERE amount > 500
)
SELECT c.customer_name, hv.order_count
FROM customers c
JOIN high_value_orders hv ON c.customer_id = hv.customer_id;
Use CTEs for readability; use subqueries in SELECT for single-value lookups.

🔄 CTE vs Subquery Comparison

Aspect CTE Subquery
Readability Very high ✅ Low for complex
Performance Medium Can be slow
Reusable Yes ✅ No ❌
📈 Module 5: Window Functions

Concepts: ROW_NUMBER, RANK, DENSE_RANK, LAG/LEAD, SUM/AVG OVER, PARTITION BY

SELECT order_id, customer_id, amount,
  ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY amount DESC) as rank
FROM orders;
Window functions compute without collapsing rows (unlike GROUP BY).

📊 Window Function Reference

Function Purpose Example
ROW_NUMBER() Unique sequential integers 1,2,3,4,5
RANK() Ranks with gaps on ties 1,2,2,4,5
DENSE_RANK() Ranks without gaps 1,2,2,3,4

✨ Module 8: Best Practices & NULL Handling

Key principle: NULL is contagious: ANY comparison with NULL returns NULL, not FALSE.

Show you think about data quality: always ask "What about NULLs?" when designing queries.

🛡️ Common NULL Pitfalls

Problem Wrong ❌ Correct ✓
NULL comparison WHERE col = NULL WHERE col IS NULL
NOT IN with NULL WHERE col NOT IN (1, 2, NULL) WHERE col NOT IN (1, 2) OR col IS NULL
Handling missing values Ignore NULLs Use COALESCE()
📅 Module 9: Date & Time Functions

Critical for reporting: Dynamic date ranges and scheduled tasks.

Always use DATE_TRUNC or DATEPART for comparisons; avoid string-based date logic.

🗓️ Dynamic Date Ranges (Most Important)

Range Query
Last 7 days WHERE proc_dt BETWEEN DATEADD(day, -7, CURRENT_DATE()) AND CURRENT_DATE()
Current month WHERE proc_dt BETWEEN DATE_TRUNC('month', CURRENT_DATE()) AND LAST_DAY(CURRENT_DATE())
Year-to-date WHERE proc_dt BETWEEN DATE_TRUNC('year', CURRENT_DATE()) AND CURRENT_DATE()
Rolling 30 days WHERE proc_dt BETWEEN DATEADD(day, -30, CURRENT_DATE()) AND CURRENT_DATE()
🧹 Module 10: SQL-Focused Data Cleaning

Why it matters: Data cleaning is 80% of data work.

Approach: identify issues → test fix → apply → verify. Always test on subset first.

🧹 Data Cleaning Techniques

Issue Detection Solution
Duplicates GROUP BY with HAVING COUNT > 1 DELETE WHERE id NOT IN (SELECT MIN(id) GROUP BY unique_col)
NULL Values WHERE col IS NULL UPDATE SET col = COALESCE(col, default)
Whitespace WHERE col LIKE ' %' UPDATE SET col = TRIM(col)

⚙️ Module 11: Stored Procedures

What: Precompiled SQL statements stored in database, executed as single unit.

CREATE PROCEDURE GetCustomerOrders @CustomerID INT
AS
BEGIN
  SELECT order_id, order_date, amount
  FROM orders
  WHERE customer_id = @CustomerID;
END;
Useful for complex logic, but keep them simple for maintainability.

⚙️ Procedure Components

Component Purpose Example

Output Parameter Return data @Result INT OUTPUT
Error Handling Catch exceptions BEGIN TRY...CATCH
🔔 Module 12: Triggers & Events

Key idea: Triggers run on data changes; Events run on schedules. Both automate database tasks.

CREATE TRIGGER log_price_change
AFTER UPDATE ON products
FOR EACH ROW
BEGIN
  INSERT INTO audit_log (product_id, old_price, new_price)
  VALUES (NEW.product_id, OLD.price, NEW.price);
END;
Use triggers sparingly — they can make debugging harder. Document well.

🔔 Trigger Types & Use Cases

Type Timing Use Case
BEFORE INSERT Before insert Validate data
AFTER UPDATE After update Audit log
AFTER DELETE After delete Archive data

INNER JOIN
Returns only rows where both tables have a match on the join key.
LEFT JOIN
Returns all rows from left, with NULLs for missing matches from right.
GROUP BY
Aggregates rows by columns; must include all non-aggregated columns.
HAVING vs WHERE
HAVING filters aggregated results; WHERE filters individual rows.
CTE
Named subquery with WITH; scoped to single statement; improves readability.
Window Function
Computes across partition without collapsing rows. Syntax: FUNC() OVER (PARTITION BY...)
ROW_NUMBER()
Unique sequential integers; never skips. Ties: 1,2,3,4,5
RANK()
Ranks with gaps on ties. Result: 1,2,2,4,5
DENSE_RANK()
Ranks without gaps on ties. Result: 1,2,2,3,4
NULL Comparison
Use IS NULL. Comparisons = <> return NULL, not TRUE/FALSE.
Subquery
Query within query. Types: scalar, IN/EXISTS, correlated.
Correlated Subquery
References outer query. Executes once per row (slower).
